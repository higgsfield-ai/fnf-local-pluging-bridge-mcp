# Gradients, materials and native effects

## Backgrounds, gradients, and travelling light

Treat atmosphere and colour flow as designed elements, with the same reference fidelity as foreground objects. Inspect several timestamps and record the palette, field positions, scale, falloff, clear/dark regions, and the path and speed of highlights. Establish whether the apparent change comes from camera motion, a moving light, changing colour, or deformation before choosing an effect.

Build broad native colour fields and soft reflection passes with Gradient Ramp, 4-Color Gradient, Gaussian Blur, Glow, bevels, and appropriate masks/mattes. Separate the base palette, low-frequency depth, diffuse illumination, and narrow specular highlights. Use a few semantic fields, not many tiny colour fragments. Avoid visible ellipse edges, bands, muddy overlaps, and a generic background that merely shares the reference hue. Add noise/evolution only if its texture and motion are visible in the reference.

For iridescent type or surfaces, match both spatial colour variation and temporal phase. A uniform fill changing hue, or a tiny point movement inside a nearly uniform gradient, may not reproduce a travelling highlight. An explicit colour-field layer with an editable text/object matte can keep effect coordinates clear. When the reference shows colour travelling across a surface, animate the field relative to the surface; transforming a surface with a fixed gradient does not recreate that independent colour phase. Verify the start, passage, and settled palette in native renders. Keep glow subordinate to the legible core and check clipping margins. If Glow washes a coloured fill to white, separate the crisp coloured core from a bloom pass underneath it, then validate the composite against the reference palette.

Validate colour/effect controls on an isolated native render, then in the final parent comp at multiple timestamps. Inspect actual rendered colours and alpha; do not infer the result from parameter values. Check coordinates after precomposition, matte order, alpha preservation, effect order, bit depth, and interpolation. If an asset renders correctly alone but incorrectly when nested, locate the first failing parent. Inspect inherited layer styles, blending, switches, and transforms; test a fresh precomp layer with explicitly restored transforms before changing the design or flattening the asset. Verify it after saving, clearing caches, and rendering a short sequence. A successful script or isolated effect test does not prove that the composed shot renders correctly. Verify a completed render rather than relying on a potentially stale preview frame.

## Native animation mechanisms

Choose a native AE mechanism that matches the observed behavior before drawing extra geometry. For a traveling light ribbon or swoosh, prefer a stable open/closed path, Stroke, Taper, and animated Trim Paths Start/End/Offset. Animate reveal and trailing disappearance independently; rotating an already visible filled ribbon does not reproduce a stroke traveling along its trajectory. Split foreground and background passes when the effect wraps around an object. Use simple masks and shared source timing to keep the two passes connected. Use Glow and motion blur only to match visible reference behavior.

For typography on a bending band, start with a live text layer and one rectangular surface in a semantic precomp, then use a native deformation such as Bezier Warp when it reproduces both the silhouette and the glyphs. Calibrate the interior text deformation in an AE render: an external geometric fit can match the boundary while stretching letters incorrectly inside it. Infer a surface from its full construction and unoccluded boundaries; a visible triangular fragment created by overlap is not necessarily the whole card. Where the reference keeps glyphs rigid, preserve their measured position, size, and orientation inside the same object rig instead of forcing them through an unsuitable warp.

Restore reference-supported secondary motion as part of the reconstruction: button hover/bounce, arrow movement, shadows, text entrances, particle births/deaths, and tails. First confirm that the motion exists in the reference. Measure the phase and amplitude of repeated motion and rebuild a small reusable keyframe cycle or a controllable expression with matching easing. Do not assume an inactive control moves just because an active one bounces. A clean static icon is not a complete reconstruction of an animated control.
