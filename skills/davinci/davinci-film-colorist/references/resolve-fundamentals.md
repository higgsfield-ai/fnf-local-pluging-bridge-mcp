# Color Interface Fundamentals

Read the current interface before acting. Panel layout, active palette, selected node, clip, graph mode, and timecode can differ from historical screenshots. Find controls by their actual names and roles rather than reused coordinates. Keep the Color page as the operating context.

Distinguish selection from modification. Selecting a node, opening a palette, renaming a node, or enabling a diagnostic view does not create the intended processing. Verify the actual value or operation and then its effect on the image. A successful API change does not establish that a particular GUI route was used.

For control training, preserve the initial state, change one meaningful control or explicitly linked set, inspect the expected response, and restore the state. Confirm restoration through readback and the image. Palette switching does not disable prior adjustments. Reset, bypass, and restoring a grade version have different scope.

Check the current Viewer scale, diagnostic mode, and source and record timecode displays. Thumbnails, Gallery preview, split-screen comparisons, and the main current Viewer can show different material or processing. Establish correspondence before comparing images or reading a scope.

When a route fails, inspect the resulting state and use another documented route only when it supports the same authorized operation. Do not repeat coordinates without new evidence or infer success from a menu closing. A partially accessible interface supports only the operations and observations actually obtained.
