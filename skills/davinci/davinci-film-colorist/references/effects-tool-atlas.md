# Effect Selection

Choose an effect by the observed task and the data it needs. Native palette operations, built-in Resolve FX, DCTL, installed third-party OFX, and an external MCP tool are distinct capabilities. A name in historical research does not establish installation, licensing, or a working control in the current host.

For a signal conversion, use an effect with a defined input and output contract. For scene balance or exposure, use the entrypoint's native technical workflow. For a creative film character, determine which tone, color, and texture components are already provided before adding another effect.

For noise and useful detail, distinguish temporal estimation, spatial smoothing, sharpening, and texture enhancement. For an object selection, distinguish signal qualification, semantic selection, estimated depth, and surface normals. They require different evidence and are not interchangeable masks.

For emitted-light effects, establish the source region and the intended spread and compositing behavior. For restoration, identify the replacement source or clean plate. For multi-input processing, confirm the real node ports and their roles before judging a control ineffective.

Read the actual control schema or current interface for the chosen effect. Menu presence, a checked field, and an accepted parameter value establish less than a visible image response. A fresh native frame, the intended diagnostic view, and the relevant movement are needed for the corresponding acceptance claims.

Select only the relevant detailed reference from the entrypoint. This atlas does not imply that every listed family has been tested, that one successful control validates the entire effect, or that a built-in effect is available in every application edition.
