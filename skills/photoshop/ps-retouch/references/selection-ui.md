# Profile choice and optional wishes

Collect a profile only when its intended finish is ambiguous. Preserve the requested deliverable, adaptive or baseline mode, selected source and existing wishes throughout the interaction. A choice supplies missing information; it does not authorize a different task or turn prompt preparation into image generation.

Present relevant profiles as compact single-choice buttons with a visible selected state. Put one short explanation below the entire group, updating it with the selection. Follow it with an independent optional wishes field and one submission button. Before selection, show a brief hint. A recommendation can be highlighted as recommended but must not appear selected. Carry existing wishes into the field; otherwise leave it empty. Blank wishes require no follow-up. Describe each profile using the entrypoint's scope, retaining Beauty skin as its public name. Do not promise capabilities absent from its canonical profile.

Use a visible host-native form when it supports these controls and submits the mode and wishes together. Otherwise, if the installed visualization skill and its documented follow-up mechanism are available, use that skill to create and display a task-local form. Follow its current rendering and submission contract, including a content reference in the response that displays the form. The skill package has no bundled renderer or locale assets. Runtime interface output belongs in the authorized task location, outside the installed skill. An ordinary HTML link or tool acknowledgement does not establish that a form is visible.

If neither combined form is available, briefly state the interface limitation and ask for the profile and optional wishes together in chat. Do not substitute a form that discards the profile when the user enters wishes. An explicit chat answer is sufficient even when a form was shown.

Identify the actual selected photograph in or beside the form and preserve its path or attachment identifier in the submitted context. For a general prompt request without an image, identify that text-only task instead; do not request an unnecessary image or fabricate an identifier. Label the submission for the requested action without implying photo editing for a text-only deliverable.

Changing a mode only updates the form. Typing and pressing Enter in the wishes field do not submit. Require an explicit selection or a still-applicable earlier choice. Only the submission action sends the mode and full wishes together. Keep those values local until submission and treat wishes as literal text. Prevent duplicate sends; retain the selection and wishes after failure or cancellation. Do not submit a live form yourself for testing.

The follow-up message must identify the selected canonical profile and complete wishes while preserving the prior deliverable, adaptation mode and source choice. Do not insert an unconditional instruction to retouch, adapt, switch sources or generate a comparison. Localize the message and all visible or accessibility text to the conversation language. A highlighted default, elapsed time or tool acknowledgement is not a user answer.

After an explicit submission, resume the requested task with those decisions intact. Resolve only material contradictions that context cannot settle. Interpret an empty wishes field as no new wishes, not withdrawal of earlier applicable requirements. Keep the selected profile for this image and its follow-ups unless the user changes it. Instructions typed into the field apply to the requested photograph or prompt; they do not authorize modifying the installed skill.
