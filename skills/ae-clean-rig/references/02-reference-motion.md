# Reference analysis and faithful motion

## Preserve animation while changing construction

1. Inspect the actual open AE project and active comp through the available bridge/API before editing. Record dimensions, frame rate, duration, media dependencies, and the current composition structure. Before structural changes, save the current state to a separate backup and create a clearly named working iteration. Do not overwrite the sole original or accidentally change unrelated compositions.
2. When a reference is supplied, read it at its real timestamps, including variable-frame-rate timing when relevant. For an edit without a reference, use the existing approved composition as the visual and motion baseline. Inspect full frames and detailed crops. Record important poses, contact/hinge points, silhouette, proportion, colors, text, entry/exit times, bounces, pauses, upgrade events, opening/closing, and audio synchronization. Do not assume motions from what an object usually does. Distinguish hard cuts and stepped events from continuous movement; preserve their exact frames rather than smoothing them into transitions.
3. Make a compact component/motion map before building. Give each independently moving part a stable identity and a sensible anchor/parent. Shared motion belongs on a parent/null. Package semantic objects and reusable controls into clearly named precompositions: a chest, each button, and a reusable effect should be independently selectable and animatable. Keep a master edit focused on a few meaningful objects. Preserve parent chains, masks, effect order, clipping margins, resolution, and foreground/background occlusion when precomposing; verify the render afterward. Use a few consistent-topology path poses for actual deformation, and transforms for translation, rotation, scale, squash, and perspective whenever they preserve the observed shape.
4. When replacing an existing object, preserve useful keyframes, expressions, timing, layer order, masks, and relationships. Rebind or measure motion when the old construction cannot supply a usable rig. Use measurements and tracking as analysis, not as the final animation structure. Build sparse pose keys at anticipation, impact, extrema, overshoot, settling, and state changes, with intentional temporal/spatial Bézier curves in the Graph Editor. Fit curves to observed motion; compare between keys as well as at the poses. Do not leave a key on every frame, merely keep every Nth key, or apply generic Easy Ease indiscriminately. Preserve direction, speed, holds, and overshoot when reducing keys. Bake dense keys only when explicitly requested or when an unavoidable downstream technical requirement has been established; do not infer an exception merely from a difficult match.
5. Validate a representative closed/static pose and an extreme/deformed pose before propagating the design across the animation. Check which design features are lost when simplifying and restore those deliberately. Preserve bounce direction, amplitude, easing, overlap, squash, lid/body interaction, and the exact ordering of events. Do not substitute a generic bounce expression for measured motion merely because it looks lively.

## Motion restraint and shared movement

Before assigning keys, annotate the motion map with both moving and stationary parts. For each proposed motion, identify the reference interval and the visible evidence: direction, amplitude, phase, acceleration, and hold. An object's expected behavior is not evidence. Leave ambiguous secondary motion still until closer inspection resolves it.

Separate camera/world movement, object transforms, genuine deformation, and changing illumination. A camera push should not also create unrelated drifting in every background field. A rotating product under a fixed light should not receive another arbitrary light orbit. Keep these causes on distinct, named controls and animate only the causes visible in the reference.

Do not invent wing flaps, tail cycles, button pressure, text rebounds, star rotation, breathing scale, or evolving noise. Add anticipation, overlap, overshoot, and settling only when supported by the reference. Repeated motion needs a measured cycle; a single gesture needs a single intentional curve. Preserve supported secondary animation when simplifying geometry.

Simplify noisy pose fits into a coherent trajectory, while retaining measured entry, contact, and exit beats. Fit 3D orientation continuously and verify projected points between poses; independently fitted Euler angles can introduce unwanted precession. Review position, orientation, scale, and apparent screen size together. Compare a real-time preview before calling the motion smoother. Check the sign changes of each visible motion against the reference: skipping a turnaround pose can make an object reverse early even when the retained poses match.
