# Construction: text, simple geometry, UI and 3D

## Choose the representation

- Use native text layers for words and numbers. Match an available font by glyph shape, weight, width, spacing, baseline, and line breaks. Use text animators, masks, or per-word/per-character text layers for motion. Keep the source editable; use outlined glyphs only where an actual custom glyph deformation requires them. State a material font substitution.
- Build graphic objects from meaningful parts: e.g. chest body, lid, trim, clasp, and shadow. Start with rectangles, rounded rectangles, ellipses, strokes, and a few clean Bézier paths. A path should represent a real continuous silhouette or detail, not a color fragment of a sampled frame.
- Add complexity only when it explains visible design or independent movement. There is no universal layer or vertex cap. Consolidating hundreds of fragments into one group or precomp does not simplify an object.
- Use an authentic clean logo asset when available. For photographs, footage, organic imagery, and details that need raster media, follow this user’s Higgsfield generation preferences below. Import and package assets at sufficient resolution for their largest on-screen size. Keep surrounding text and simple graphics native.
- Use actual gradients, soft shadows, controlled highlights, strokes, and glows. Do not approximate continuous shading with stacks of quantized color bands or tiny polygons. Blur is not a substitute for fixing fragmented construction; do not soften the entire composition to hide a local defect.
- Do not use per-frame auto-tracing, palette segmentation, or disconnected contour replacement as the primary reconstruction method. Computer vision may measure timing, colors, bounds, and motion, but should drive a stable object rig rather than regenerate its topology every frame. A reference video layer may be a guide or comparison, not a hidden replacement for an editable reconstruction.

## This user’s construction requirements

- Build buttons, input fields, prompt windows, dialogs, panels, and their states inside AE from native text, simple shapes, gradients, and built-in effects. Keep each control in a semantic precomp. Do not generate UI images, use rasterized UI material plates, or embed screenshots of controls as final artwork. A complex glass look still needs a native controllable construction: continuous geometry, bevels, gradient/reflection passes, displacement, blur, and highlight animation as appropriate.
- Never cut an object out of a reference screenshot with a mask and present it as the finished asset. Reference crops are for analysis and comparison only. Obtain an authentic standalone asset with clean transparency, construct a compact native rig, or use an explicitly authorized original generated asset when appropriate. A logo or character visible inside a phone screenshot is not a standalone source asset.
- For phones and other volumetric products, match physical depth, bevels, side details, material response, perspective, and changing light with actual 3D geometry and a camera when visible in the reference. A flattened precomp with Corner Pin, or merely enabling a flat layer’s 3D switch, is not a substitute. Prefer native AE extrusion/3D when it serves the object, otherwise package an editable 3D source and its required renders/model. Keep screen UI editable in AE and verify its registration throughout the move.
- Improve animation through measured staging, continuous velocity, motivated acceleration, overlap, anticipation, overshoot, and settling. Use a shared object/camera rig for coherent motion and sparse intentional curves. Do not add random wobble or generic bounce to disguise missing reference motion. Check transitions and intermediate frames at playback speed after rebuilding materials or geometry.
