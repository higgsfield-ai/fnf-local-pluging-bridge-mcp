# Verification, Rendering, and Delivery

## Structural and motion evidence

Compare protected transforms, geometry, materials, hierarchy, visibility, and camera data against the correctly evaluated baseline. Confirm source face coverage after partitioning and the absence of temporary geometry and instances in the final state. Check the intended empty start across all renderable object types.

Inspect repeated families for actual matching construction, including their evaluated instances. Verify deformation reset and absence of returning keys after settlement. Use current projected bounds to locate framing risks, then inspect rendered images for occlusion. Important construction must remain visible while the scene develops.

## Handoff and visual comparison

Compare source and assembled states at the same camera, dimensions, display profile, and reference pose. Keep native lighting and materials separate from temporary Solid export settings. Mesh partition boundaries can change cavity or normals; returning native sources after geometric alignment can remove these differences. Inspect the handoff without overlapping both representations.

Compare a candidate handoff frame with and without temporary internals. Correct visible exposure before removal. Movement between adjacent frames is not a valid isolated measure of handoff error when the camera or subject is also moving.

State pixel differences according to the evidence. Exact agreement between isolated still renders does not prove bitwise identity of the sequential video. Antialiasing, shadow behavior, and caches can differ between those rendering paths. Investigate visible discrepancies and distinguish measured geometric agreement from renderer-dependent image differences.

## Sequential render and review

Prefer Blender's native animation rendering mode for a complete sequence when it is substantially faster than separate still renders. Use a current isolated checkpoint for background rendering when that keeps the live application responsive. Confirm that it contains the correct scene, action state, camera, and dependencies.

Use one documented Workbench profile for Solid output and its baseline. If large surfaces exhibit Workbench shadow artifacts, inspect the source under that same profile before attributing the defect to assembly. A justified export-profile adjustment must be applied to both comparison renders and must preserve the native scene's lighting setup.

Render the full current sequence and inspect actual video playback. Contact sheets and active-curve counts cannot establish smooth rhythm or absence of cached-geometry problems. Check that the main action remains legible, mechanisms appear distinct, and repeated families remain consistent. Confirm the decoded frame when using playback or seek controls.

After any relevant revision, regenerate affected outputs and dependent passes. Verify current export logs, frame count, frame rate, duration, dimensions, codec, and decoded media. Keep export parameters separate from animation retiming. File existence alone is insufficient evidence of a fresh successful export.

## Save and transmit

Save the agreed result and reopen it to verify scene persistence, active camera, and animation range. Leave the live application in useful shading and respect any frame the user is currently inspecting. Keep intermediate files, backups, and review history outside the deliverable package.

Deliver through the user's authorized channel. Reuse authorization already established for the same result and recipient, and never infer another destination from stored project notes. Before transmission verify the exact filename, recipient, and attachment preview. Afterward confirm the delivered file identity and transport status; a correct caption does not prove that the correct attachment was sent.

Summarize the visible mechanics, camera changes, duration, preservation evidence, and any unresolved limitation. Identify temporary internal construction as approximate when that affects how the result should be understood.
