# Optional process case study

Use only when the user requests a process demonstration or media-kit composition in addition to the Blender assembly.

Inspect the actual open template: application edition, file, active composition, dimensions, frame rate, layer sources, parent transforms, masks, logos, music, and timing. Save a recovery copy of live state. Duplicate the requested main composition and only the content branches that need independent edits; replacing a shared FootageItem can change the original template as well.

Measure the template's content apertures and preserve its chrome, logos, layout, and music when requested. Fit the complete hero video inside its aperture without cropping important assembly. A square media-kit wrapper can contain the requested 16:9 scene montage; preserve the wrapper's established layout unless the user asks to redesign it.

Create a single timing map for the hero, interface recording, and prompt narrative. Match each segment to the same scene and construction stage. For a time-lapse, record or stage meaningful interactions with the actual editable project: functional parts, attachment controllers, animation curves, environment assembly, and camera checks. Keep the cursor, selected controls, and resulting scene states consistent. Retiming a recording does not excuse showing unrelated buttons or a different project.

When reconstructing missed process footage, present it as a process replay or demonstration. Translate or summarize prompts faithfully, without claiming that translated wording is a verbatim historical log. Exclude unrelated conversations and private data from captures. Screen recording, a staged cursor overlay, or editable native chat graphics can be selected according to the user's requested format; do not silently substitute a static still for a requested recording.

Verify a short sample from the actual recorder before a long take. An app-specific accessibility screenshot can show a background window while a display recorder captures a different foreground app. With multiple displays, verify the recorded display and visible window; do not infer the source from a successful UI click. Keep the recorder's original project locally and trim away setup footage before delivery. For timed demonstrations, record the capture start and action start so all four scene boundaries can be aligned exactly. A reconstructed cursor must point to the control whose visible state changes, and the translated chat copy should remain editable.

Extend content and music to the requested duration without slowing the assembled hero or adding unwanted transition effects. Keep new overlays and text editable. Inspect the complete exported wrapper in playback: synchronized segments, readable lower panels, preserved logos, framing, sound, first/last frames, duration, and frame rate.

Check the decoded recording's actual frame count, not just the requested recording or trim duration. A nominal 25-second recording can contain only 598 frames at 24 fps. Map the last output frame to a valid source frame and extend the layer's out-point, so the interface does not disappear at the end. Inspect both sides of every scene cut: UI redraw latency can shift a recorded scene change by one or two frames. Use a per-scene time map to align the recording to the hero cuts without pulling the next scene into the preceding shot.

Deliver the native project and authorized exports. Verify actual transmission before marking delivery complete. Follow the most recent instruction about keeping the computer awake or shutting it down; these are session-specific actions, not default skill behavior.

When multiple AE editions are running, target the exact edition and read back its project path and version. If native scripting dispatches through BridgeTalk, retain and inspect error callbacks: a successful send only proves message acceptance. ExtendScript uses an older JavaScript grammar; avoid reserved identifiers such as `short` even for object fields. Inspect actual render output before repeating a timed-out mutation, so the retry cannot duplicate content branches.

In AE, removing every time-remap key can disable time remapping and hide the property. Add the intended keys first, then remove obsolete default keys while retaining the new ones. Verify the final rendered frame after the change; a saved project or a middle-frame preview is insufficient.
